What this is

A Pune hotel concierge chat. The browser talks to a FastAPI client. The client talks to Claude. Claude calls 16 MCP tools. Those tools read and write MongoDB — hotels, bookings, and users.

Dummy bookings are real database records, not memory. A guest can only view, change, or cancel stays booked with their own email and 10-digit mobile. There is no payment gateway. Chat is ordinary HTTP POST /chat (not Socket.IO).

How to run locally

  1. Confirm HOTEL-CHATBOT-CLIENT/.env has ANTHROPIC_API_KEY.
  2. Confirm HOTEL-CHATBOT-MCP/.env has MONGODB_URI and MONGODB_DB=hotel_chatbot.
  3. Start the client (it also starts the MCP server as a child process):
cd HOTEL-CHATBOT-CLIENT
./.venv/bin/python app.py

Open http://127.0.0.1:8000. Stop with Ctrl+C, then start again after Python changes (no auto-reload).

Never paste the Claude key or MongoDB password into the chat UI, this HTML, or frontend JS.

Deploy on Render (step by step)

Deploy one web service. The MCP hotel tools run as a child process inside the same Docker image. Hugging Face Docker Spaces are paid for many free accounts, so this project uses Render.

Public GitHub repo: github.com/shelarrohit45/Hotel-ChatBot

1. Push the code to GitHub

Do not commit .env files. From the project root:

git add -A
git status    # confirm no .env files
git commit -m "Deploy hotel chatbot"
git push origin main

2. Allow MongoDB Atlas from the internet

  1. Open cloud.mongodb.com and sign in.
  2. Network Access → Add IP Address.
  3. Click Allow Access from Anywhere (0.0.0.0/0) → Confirm.

Without this, Render cannot reach the hotel catalog.

3. Create a Render web service

  1. Open dashboard.render.com and sign in with GitHub.
  2. New → Web Service.
  3. Connect the repo shelarrohit45/Hotel-ChatBot (or your fork).
  4. Set:
    • Runtime: Docker (uses the repo-root Dockerfile)
    • Branch: main
    • Instance type: Free

4. Add environment variables

In the Render service → Environment. Copy values from your local .env files. Do not put them in GitHub.

NameValueWhere it comes from
ANTHROPIC_API_KEYyour Claude keyHOTEL-CHATBOT-CLIENT/.env (secret)
ANTHROPIC_MODELclaude-haiku-4-5same as local, or the model you use
MONGODB_URIAtlas connection stringHOTEL-CHATBOT-MCP/.env (secret)
MONGODB_DBhotel_chatbotdatabase name
COOKIE_SECUREtruerequired on HTTPS

Docker already sets MCP paths inside the image. You do not need the Mac MCP_SERVER_* paths on Render.

5. Deploy and open the URL

  1. Click Create Web Service (or Manual Deploy after a git push).
  2. Wait until logs show Hotel chat API ready and Uvicorn listening.
  3. Open the URL Render gives you, for example:
    https://hotel-chatbot-42t0.onrender.com/

What to expect on the free plan

  • The service sleeps after idle. The first visit can show a plain “Not Found” for about a minute. Wait, then refresh.
  • Anyone who uses the live chat spends your Claude credits.
  • After each git push origin main, Render rebuilds if auto-deploy is on.

If search says the database is down

  1. Confirm MONGODB_URI and MONGODB_DB are set on Render (not only on your Mac).
  2. Confirm Atlas Network Access includes 0.0.0.0/0.
  3. The MCP child process must inherit those env vars (handled in CLIENT/mcp_bridge.py).

Guest profile

First visit asks for name, email, and 10-digit mobile. That profile is stored in MongoDB users and kept in the session cookie until Log out. Bookings reuse those details — the chat does not ask again. 

GET  /auth/me       → { user }
POST /auth/guest    → save name, email, mobile
POST /auth/logout   → clear session
POST /chat          → 401 until the guest form is saved

Cancel, modify, and “my bookings” only work for reservations that match this guest’s mobile and email. Another person who knows a BK-… id cannot change it.

Try in chat

Find hotels in Pune for 2 guests from 10 to 12 Sep 2026
Book Courtyard Hinjewadi
What are my bookings?
Cancel BK-1001

How a question travels

Browser  The Desk UI
  → POST /chat   (httponly cookie hotel_sid, no API key)
  → guardrails   (jailbreak, topic, rate limit 20/min)
  → Claude       (system = CLAUDE.md + skills.md)
      if tool_use:
        → allowlist (16 names)
        → inject signed-in guest into book / list / cancel / modify
        → MCP stdio  HOTEL-CHATBOT-MCP/server.py
        → tools.py   → MongoDB hotel_chatbot
  → JSON { text, blocked }
  → chat UI  (tool names are never shown)

MongoDB

Database name: hotel_chatbot. URI lives in HOTEL-CHATBOT-MCP/.env locally, and in Render environment variables in production.

CollectionKeyContents
hotelshotel_id e.g. HTL-PUN-01350 Pune hotels, rooms, rates, reviews, amenities.
users10-digit mobileName, email, booking_ids.
bookingsbooking_id e.g. BK-1001Hotel, room, dates, guest, status, total INR. Cancel sets status to cancelled; the row stays.
sessionscookie idLogged-in guest until Log out.
countersbooking_seqNext booking number.

create_booking uses the signed-in name, email, and mobile. list_bookings / cancel_booking / modify_booking require that same mobile and email.

Guardrails

  • Browser never sees the Claude key or Mongo URI.
  • Jailbreaks and secret-shaped text are refused before Claude.
  • Only the 16 hotel tools may be called.
  • A guest can only change bookings that match their mobile and email.
  • 20 requests per minute per session cookie.
  • CSP: scripts from 'self' only; connect-src 'self'.
  • Chat replies do not list internal tool names.
